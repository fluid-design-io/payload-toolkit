# Implementation review

Reviewed the CLI, operation owner and private adapters, registry qualification and import checks, contributor fixtures, workflows and trusted reporter on 2026-10-07. Product source was not edited. The findings below describe the source observed during the review. Other agents were making fixes concurrently, so rerun the stated checks against the final tree.

## Findings

1. **P1. Cancellation can finish while a descendant still writes.** In [attempts.ts](/Users/oliverpan/Desktop/Tutorials/payload-better-auth-starter/src/operations/private/attempts.ts:148), abort schedules a process-group SIGKILL, but the direct child's close handler cancels it at line 174. A descendant that ignores SIGTERM and closes inherited output survives. An owned reproduction returned `interrupted` while its descendant remained alive and its heartbeat increased from 1 to 86 bytes after 2.25 seconds. The operation can then release its target lease while that process keeps writing. Await process-tree termination before settling the promise. Windows needs tree termination too, since its current branch calls only `child.kill`. Add a descendant test to the shared process runner, beyond the registry worker's existing test.

2. **P1. Git observation failures bypass dirty-project policy.** [project.ts](/Users/oliverpan/Desktop/Tutorials/payload-better-auth-starter/src/operations/private/project.ts:42) catches every Git error and returns null. Snapshot converts failed status and staged-entry reads into empty values at lines 128 and 136. Under Node 24.21.0, a controlled Git shim made only `git status` exit 128 in a repository containing an untracked developer file. `requireClean(snapshot, false)` accepted it. Distinguish an absent repository from failed required observations and block the latter. Preserve valid unborn-HEAD and detached-branch cases separately. Test failed status/index reads and unavailable Git.

3. **P1. Agent success ignores destruction of the starting Git index.** [agents.ts](/Users/oliverpan/Desktop/Tutorials/payload-better-auth-starter/src/operations/private/agents.ts:146) records the final snapshot and returns completed without checking HEAD or index identity. The generated prompt at line 105 also omits an explicit prohibition on stash, reset, staging and commits. Under Node 24.21.0, an owned fake Codex removed `developer.txt` from the starting index and emitted `turn.completed`; the adapter returned completed with the index empty. Explicitly prohibit these actions in handoff guidance and reject successful agent status when HEAD/index preservation fails. Retain observations rather than resetting developer state. No paid model was invoked.

4. **P2. Product subprocess dispatch lacks the fixture's Windows launcher.** [attempts.ts](/Users/oliverpan/Desktop/Tutorials/payload-better-auth-starter/src/operations/private/attempts.ts:129) directly spawns executable names with no shell or Windows script resolution. Official bootstrap calls it with `npm`, and completion calls it with the selected manager. Standard Windows npm/pnpm installations expose command shims, while [support.ts](/Users/oliverpan/Desktop/Tutorials/payload-better-auth-starter/scripts/fixtures/support.ts:61) already routes those tools through their JavaScript launchers. Move that portable handling into product-owned process dispatch. Exercise installer dispatch in a controlled Windows fixture. Current Windows CI invokes only packed help/error checks, so its success would not establish this path. This is a source-backed platform concern; Windows execution was unavailable here.

5. **P2. The current import-boundary gate fails its own tests.** [check-boundaries.ts](/Users/oliverpan/Desktop/Tutorials/payload-better-auth-starter/scripts/check-boundaries.ts:48) permits only an adapter's matching test to import that adapter. Running this script with Node 24.21.0 failed on `agents.test.ts` importing `./attempts.js` and `official.test.ts` importing `./project.js`. These are existing test imports, so the current tree cannot pass `pnpm check` through its lint stage. Put fixture setup in the owning tests using native Node APIs, or restructure ownership with an explicit narrow rule that preserves production adapter boundaries. Rerun the actual gate.

### Additional findings from the resolution review

**P1. Installation does not reject loss of the starting repository.** [project.ts](/Users/oliverpan/Desktop/Tutorials/payload-better-auth-starter/src/operations/private/project.ts:197) compares Git identity only when both snapshots contain Git. In an owned Node 24.21.0 reproduction, renaming the project's `.git` directory outside the target changed `before.git` from present to absent in `after.git`. `requireExpectedChanges(project, before, after, [])` still accepted it. Check Git-presence changes before the source-root shortcut. The agent guard already does this. This is a reproduced installation-policy defect, independent of the now-fixed Git command failure handling.

**Windows cancellation failure remains a source-backed concern.** [attempts.ts](/Users/oliverpan/Desktop/Tutorials/payload-better-auth-starter/src/operations/private/attempts.ts:218) resolves its tree-termination promise on a taskkill launch error and on every taskkill exit code. The launch-error fallback kills only the parent. A failed tree stop therefore does not establish that descendants stopped before the operation releases its lease. Handle failed termination explicitly and retain evidence of uncertain ownership. Native Windows was unavailable, so this failure case was not reproduced.

### Final containment review

The two additional findings above are resolved in the revised source. An independent Node 24.21.0 rerun now rejected loss of the starting repository with `external-drift`.

Windows tree termination now uses a bounded helper that rejects failed execution, a missing launcher and timeout with `termination-unconfirmed`. A controlled hanging executable returned that typed failure after 10,003 milliseconds. The operation records uncertain termination, exits unsuccessfully and retains a lease marked `recoveryRequired`. An independent retry against that marker rejected with `target-busy` even after its recorded parent was absent. The registry worker uses the same helper and propagates uncertain termination into the operation. Native Windows execution remains unverified; these results cover portable failure handling and source ownership.

A further force-kill case exposed automatic stale-lease reclamation. Before its fix, an owned toolkit parent launched a detached writer and acquired the target lease. Killing only the parent's recorded PID left the writer alive, with its heartbeat increasing from one to six bytes. A retry still reclaimed that lease. This established that a dead parent did not prove its writers had stopped.

The final lease implementation does not automatically reclaim existing leases. Repeating the same force-kill reproduction left the controlled writer alive with the same heartbeat growth, but the retry now rejected with `target-busy` and required manual ownership review. Both the failed and corrected reproductions force-cleaned the exact recorded child PID and removed only their owned temporary state. The fix contains uncertain writers; it does not claim that SIGKILL permits automatic cleanup.

The final focused operation and registry run passed all 24 tests under Node 24.21.0, including normal dead-owner leases, recovery leases, repository loss, cancellation descendants and typed Windows termination failure. The import-boundary checker passed again. These checks close the source-backed findings recorded in this review. They do not establish the full installer/database/browser matrix, native Windows runtime behavior or paid-agent quality.
