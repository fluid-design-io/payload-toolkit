# External registries

Run `bun run agent:verify:external` for live source installation from Payload Components. The command builds and packs the toolkit, installs the tarball in an isolated npm consumer, and generates the pinned official Next.js app with Postgres configuration using pnpm 10.34.6. It installs Hero Split by URL without toolkit metadata or a guide, checks its source and `badge` dependency, checks the integration handoff, and repeats installation through `@payload-components/hero-split`. It verifies that the installed Payload version and upstream block files remain unchanged. An owned compiled mock `codex` executable receives the contextual prompt. The command checks process success, required process failure, and the separate installation and verification outcomes. An edited-file collision must preserve the edited bytes. The fixture restores its own edit before runtime. This explicit command requires network access. The default repository checks do not invoke it.

Run `bun run agent:verify:external --runtime` for the known Next.js and Postgres integration. Install Chromium first with `bun x playwright install chromium`. The runtime command starts its own database and server. It supplies fixture implementations for the missing `CMSLink`, `Media`, `linkGroup`, and `cn` imports, registers Hero Split in a Pages collection, and mounts the installed renderer. The fixture caller normalizes a nullable block ID to the upstream renderer’s optional string prop. It adds the missing `class-variance-authority@0.7.1` baseline dependency and supplies scoped fixture CSS. The check proves data and rendering integration, not upstream theme parity. These writes apply only to the pinned fixture. They are not a general host integration mechanism.

Runtime acceptance regenerates Payload types and the import map, builds the app, and typechecks. It creates an admin through native first-user registration, checks that first-user registration closes, and checks that anonymous Page writes fail. Authenticated REST uploads an image and creates a Page with the upstream block. The verifier reads the saved Page and checks its block type, title, and media relationship. Playwright checks the rendered heading, CTA, highlight, loaded image, and existing Page in native admin. Page creation uses REST. This check does not prove block selection or saving through the admin editor.

Each attempt retains `evidence.json`, command logs, the packed tarball, installation results, the frozen external registry graph, and fixture source under `.scratch/verification/<run-id>`. Runtime screenshots and browser and server logs are retained beside them. Inspect the screenshots before claiming visual review. Live upstream changes can fail an attempt. Preserve the failed evidence and inspect the changed source before updating the fixture.

No paid model runs in either mode. Installation, fixture integration, database behavior, browser assertions, and screenshot inspection are separate evidence. An agent handoff prompt proves instructions were produced, not that an agent completed them. Missing Node 24.21.0, Bun 1.4.2, pnpm 10.34.6, Chromium, or database capabilities are blocked evidence. Cleanup checks owned workspace markers and database labels. Supplied services require `TOOLKIT_TEST_DISPOSABLE=yes` and are never dropped.

Real Codex checks use ordinary Git projects. A generated app without Git can fail Codex's trust check after source installation succeeds. Keep that prerequisite failure separate from registry compatibility; the toolkit reports it without bypassing trust or changing application Git state. Operation tests cover the fixed diagnostic and keep other agent output private.
