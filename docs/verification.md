# Verification

`pnpm run agent:verify -- --cli-only` verifies the actual packed binary through an isolated consumer. `pnpm run agent:verify -- --installation-only --package-manager npm` drives real packed init/add and records the output lockfile and installed dependencies, without database/browser checks. Use `bun` or `pnpm` for the other installers. `pnpm run agent:verify -- --framework next --database postgres` additionally creates an official project, adds Forms, applies known guide integration, runs codegen/build/typecheck and drives real REST/browser behavior. Repeat with TanStack and MongoDB. Output package-manager coverage uses `--package-manager npm` and `--package-manager bun`; install that manager first.

Install Chromium with `pnpm exec playwright install chromium`, adding `--with-deps` on Linux. Docker is the default disposable service provider. Each container has a unique run name, random mapped localhost port and ownership label. The Mongo fixture initializes a single-node replica set. For a host without Docker, provide `TOOLKIT_TEST_POSTGRES_URL` or `TOOLKIT_TEST_MONGODB_URL` and `TOOLKIT_TEST_DISPOSABLE=yes`. These URLs must identify disposable test data; fixtures write users/forms/submissions but never drop borrowed databases. Do not use production URLs.

Read the portable [verification skill](../.agents/skills/verify-payload-toolkit/SKILL.md) for selectors, observable completion conditions and teardown. Missing runtime capabilities exit 2 and produce blocked evidence. Test failures exit 1. Neither counts as success. Initial canary incompatibilities remain failures rather than skipped checks.

Results live in `.scratch/verification/<run-id>/evidence.json`, alongside sanitized logs and browser screenshots. The record binds checks to Git revision/dirty source digest, packed package, bootstrap/catalog, fixture lock and integrated source. Cleanup preserves these files. Use `pnpm run agent:evidence` and `pnpm run agent:cleanup`, optionally with `--run <run-id>`.

The unprivileged workflow checks the contributed revision on Ubuntu plus Windows/macOS installation checks, Linux npm/Bun installation checks and four Linux pnpm runtime cells. It has no model credentials or writable PR token. Its separate default-branch reporter validates GitHub run/PR/head/job identities, parses bounded JSON artifacts without extraction or execution, and updates one proof comment. Contributed evidence is labeled separately from platform CI conclusions; changed PR heads are marked stale. The reporter becomes available only after its trusted script and workflow exist on the default branch. No PR comments are posted during local verification.

The comment has three rows: checks, installation and Forms runtime. Each row counts successful GitHub jobs and names any failed, cancelled or missing cells. It links the tested revision, its code changes and available Actions artifacts, with expiration dates. Parsed receipt claims remain separate from those job results.

For review, select zero to two useful captures from the retained artifacts. Changes without visible behavior need no image. A visible feature usually needs one representative screenshot; a visible bug may need a before/after pair. Avoid a capture for every file or test. Report browser assertions and an agent's visual observations separately. A captured screenshot does not prove that someone inspected it. This workflow links artifacts and does not upload inline media to comments.

Behavior boundaries remain explicit. Controlled HTTP failure proves client error handling; real database checks prove persistence/access. Console notification proves invocation tied to a saved ID, not external email delivery. Known fixture wiring proves the supported official hosts, not arbitrary agent integration. Typechecking/building cannot replace runtime or browser evidence.
